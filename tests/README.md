# SQL 통합 테스트 규약

`tests/integration`의 SQL 파일은 이름 오름차순으로 실행합니다. 현재 순서는 배포 확인,
기능 동작, 모델 무결성, seed 멱등성, 저장 프로시저 경계값, 인덱스 메타데이터입니다.
각 파일은 `eng/Test-Database.ps1`의 임시 SQL Server와
`eng/Test-DeployedDatabase.ps1`의 SQL MI에서 동일하게 실행되어야 합니다.

## 작성 규약

- 파일명은 `NNN-description.sql`이며 앞 번호는 실행 순서를 고정합니다.
- 실패는 반드시 `THROW`로 알리고 이 저장소 범위의 `51xxx` 오류 번호를 사용합니다.
- 여러 번 실행해도 같은 결과가 나와야 하며 테스트 전 상태에 의존하는 임시 이름을 피합니다.
- 데이터를 변경하는 테스트는 명시적 트랜잭션 안에서 수행하고 성공 경로에서
  `ROLLBACK`합니다. 테스트 목적상 영구 데이터가 필요하면 고유 키로 정리 절차를 함께 둡니다.
- `GO` 의존, 로컬 파일 `:r`, 클라이언트별 SQLCMD 확장은 두 실행기의 동작이 다를 수
  있으므로 통합 테스트 파일에서 사용하지 않습니다.

현재 모델에는 테이블 간 FK가 없습니다. 따라서 존재하지 않는 관계를 가정하지 않고
`FeatureFlag.FlagName` 기본 키, 비어 있지 않은 안정 식별자, seed 단일 행을 현재 모델의
무결성 invariant로 검증합니다. 관계형 테이블이 추가되면 FK 존재와 orphan 부재 검사를
그 변경과 함께 추가합니다.

운영 DB에서 직접 실행하면 트랜잭션 안에서도 잠금과 로그가 발생할 수 있습니다. 먼저
Dev/Test에서 실행하고, 운영에서는 승인된 점검 시간과 읽기/쓰기 범위를 확인한 뒤
`Test-DeployedDatabase.ps1`을 사용하십시오. tSQLt는 SQL MI의 CLR 호환성, 조직 보안
정책, 유지보수 비용에 대한 공식 근거를 확인한 뒤 결정할 **도입 검토 항목**이며 현재
테스트 경로에는 포함하지 않습니다.
